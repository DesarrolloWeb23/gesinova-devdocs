# Gesinova DevDocs

Portal oficial de documentación de **Gesinova**, desarrollado con Docusaurus.

Este sitio centraliza la documentación técnica, manuales de usuario, procedimientos operativos, arquitectura de software, guías de despliegue y registro de cambios de la plataforma Gesinova.

## Objetivo

Proporcionar una fuente única y actualizada de conocimiento para:

* Desarrolladores.
* Analistas funcionales.
* Coordinadores.
* Equipo de soporte.
* Administradores del sistema.
* Usuarios finales.

## Contenido

La documentación está organizada en las siguientes secciones:

### Manuales de Usuario

Guías funcionales para el uso de los diferentes módulos de Gesinova.

### Procesos

Documentación de los procesos operativos y administrativos soportados por la plataforma.

### Documentación Técnica

Información destinada al equipo de desarrollo:

* Arquitectura del sistema.
* Estructura de proyectos.
* Integraciones.
* Servicios y APIs.
* Base de datos.
* Procedimientos almacenados.
* Buenas prácticas de desarrollo.

### Despliegue e Infraestructura

Documentación relacionada con:

* Ambientes de desarrollo.
* Pruebas.
* Producción.
* Configuración de servidores.
* Automatización de despliegues.

### Actualizaciones

Registro histórico de cambios, mejoras y correcciones implementadas en Gesinova.

## Tecnologías Utilizadas

* Docusaurus
* React
* TypeScript
* Markdown (MDX)
* Node.js

## Instalación

Clonar el repositorio:

```bash
git clone <url-del-repositorio>
cd gesinova-devdocs
```

Instalar dependencias:

```bash
npm install
```

Iniciar el entorno de desarrollo:

```bash
npm start
```

El sitio estará disponible en:

```text
http://localhost:3000
```

## Construcción

Generar la versión de producción:

```bash
npm run build
```

Los archivos generados se almacenarán en:

```text
build/
```

## Despliegue

Para publicar la documentación:

```bash
npm run build
```

Posteriormente, desplegar el contenido generado en el servidor web correspondiente.

## Convenciones de Documentación

* Mantener los documentos actualizados.
* Utilizar títulos y subtítulos descriptivos.
* Incluir ejemplos cuando sea posible.
* Documentar cambios relevantes en la sección de actualizaciones.
* Mantener consistencia en nombres de módulos, procesos y componentes.

## Contribución

Antes de realizar cambios en la documentación:

1. Crear una rama de trabajo.
2. Realizar los cambios necesarios.
3. Validar localmente el sitio.
4. Crear el Pull Request para revisión.

## Soporte

Si encuentra errores o información desactualizada, comuníquese con el equipo responsable de Gesinova para su revisión y actualización.
